Ce que cette relecture contrôle

Sur un compromis ou une promesse, quatre points, et seulement ceux-là : les travaux déjà réalisés qui touchent le gros œuvre ou l'extérieur du bien (une autorisation d'urbanisme est alors exigible, et la garantie décennale court encore si les travaux ont moins de dix ans) ; les diagnostics périmés à ce jour ; les entretiens et documents que le vendeur doit fournir ; les travaux qu'il s'est engagé à faire avant la vente. Le reste (préemption, servitudes, urbanisme général) n'est volontairement pas contrôlé ici : un rapport court se lit, un inventaire ne se lit pas.

Sur un projet d'acte de vente, le projet est comparé à l'avant-contrat signé : parties, prix, désignation du bien, et surtout les engagements du vendeur — un engagement n'est tenu que si un justificatif le prouve et que sa date est encore valable au jour de la relecture.

Envoi des messages

Tous les messages de CLAIRE sont envoyés à cette adresse. C'est leur arrivée qui déclenche le flux Power Automate, qui poste ensuite le message dans Teams à la personne concernée.

Pour Microsoft 365 : smtp.office365.com, port 587, avec un compte et un mot de passe d'application (voir la procédure plus bas). L'envoi sans compte n'est possible que si l'enregistrement SPF du domaine autorise l'adresse IP du bureau — ce n'est pas le cas quand le courrier passe par une passerelle de filtrage.

587 pour un envoi avec compte (le cas courant), 25 pour un envoi sans compte, 465 pour un serveur en TLS direct.

Microsoft 365 exige que l'expéditeur soit le compte SMTP lui-même, sauf droit « Envoyer en tant que » accordé à ce compte. Laisser vide est le plus sûr : le compte sert alors d'expéditeur.

La boîte aux lettres qui envoie les messages. L'authentification SMTP doit être autorisée pour elle côté administrateur Microsoft 365. Laisser vide uniquement pour un envoi sans compte, si le SPF du domaine l'autorise.

Un mot de passe d'application si le compte est protégé par authentification à deux facteurs. N'est jamais réaffiché une fois enregistré : laisser ce champ vide conserve celui déjà en place. Stocké sur le serveur de l'étude, dans le fichier de la base.

Comment ça marche

CLAIRE envoie un email à la boîte-passerelle. Son objet contient l'adresse du collaborateur à prévenir, son corps le message. Le flux Power Automate, déclenché par l'arrivée de cet email, lit l'objet pour savoir à qui poster le message dans Teams.

Le flux est déjà créé et activé (déclencheur « Quand un nouvel e-mail arrive » sur cette boîte, puis action Teams). Il n'y a rien à refaire dans Power Automate : seuls les réglages d'envoi ci-dessus sont à renseigner.

Renseigner le serveur d'envoi
  1. Autoriser l'authentification SMTP pour la boîte qui enverra les messages : centre d'administration Microsoft 365 → Utilisateurs → la boîte concernée → Courrier → Gérer les applications de messagerie → cocher SMTP authentifié. Ce réglage est souvent désactivé pour tout le locataire par défaut : l'administrateur doit alors l'autoriser au moins pour cette boîte.
  2. Créer un mot de passe d'application si ce compte est protégé par authentification à deux facteurs (le cas habituel) : le mot de passe habituel ne fonctionne pas pour SMTP.
  3. Remplir ci-dessus : serveur smtp.office365.com, port 587, « Connexion chiffrée dès l'ouverture » décochée (le chiffrement est négocié en cours de connexion sur ce port), compte = l'adresse de la boîte, mot de passe = le mot de passe d'application. Laisser l'adresse d'expédition vide.
  4. Renseigner la boîte-passerelle (celle sur laquelle le flux est déclenché), l'adresse email de chaque collaborateur, optionnellement une adresse de copie, cocher « Activer l'envoi automatique de rappels », puis Enregistrer.
  5. Utiliser le bouton « Tester » à côté de chaque collaborateur : un message de test doit arriver dans son Teams. S'il n'arrive pas, l'historique du flux dans Power Automate indique s'il s'est déclenché — email bien arrivé mais pas de message Teams : le problème est dans le flux ; aucune trace : le problème est côté envoi, et le message d'erreur affiché sous le bouton le précise.

Pourquoi un compte est nécessaire ici. Microsoft 365 accepte aussi un envoi sans compte depuis le réseau du bureau, mais seulement si l'enregistrement SPF du domaine autorise l'adresse IP de sortie du bureau. Quand le courrier du domaine passe par une passerelle de filtrage — c'est le cas de cette étude, dont le SPF n'autorise que le prestataire de filtrage et refuse tout le reste — un envoi depuis le bureau serait rejeté ou mis en quarantaine. Le compte authentifié contourne entièrement ce point : le message part de la boîte elle-même, et le destinataire étant une boîte du même locataire, la remise est interne.

Les rappels sont envoyés automatiquement 15 puis 7 jours avant chaque échéance active d'un dossier (vente préalable, prêt, date butoir, appel de fonds, rendez-vous de signature, échéance personnalisée), au responsable du dossier — jamais deux fois pour la même échéance. L'adresse de copie ci-dessus, si renseignée, reçoit le même message pour chaque envoi. Il n'existe plus de rappel par email manuel à envoyer soi-même : ce mécanisme le remplace entièrement.
