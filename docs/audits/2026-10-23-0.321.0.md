# Audit de la version 0.321.0 (23/10/2026)

Périmètre : Yousign branché à « Demander à CLAIRE » (client MCP côté serveur, routes, outils de l'agent, carte « Autoriser », réglages). Audit par un second agent, lecture seule, sans accès à Yousign.

**Verdict : à corriger avant usage réel — corrigé** (deux points « Haut » traités avant l'envoi).

| Prio | Point | Suite donnée |
|---|---|---|
| Haut | H1 — le serveur ne vérifiait pas l'autorisation : un appel direct sur `/api/yousign/appel` pouvait envoyer | Corrigé : une écriture n'est faite que si l'agent l'a demandée (appel émis par le serveur, arguments identiques, une fois, 10 min) ; test « appel d'écriture sans demande = refusé » |
| Haut | H2 — la carte « Autoriser » cachait signataires et nom de la demande | Corrigé : arguments imbriqués, emails entiers, demande relue (nom, état, signataires) ; tests |
| Moyen | M1 — un refus de schéma dû à Yousign suspendait OpenLegi | Corrigé : retrait par famille, Yousign d'abord |
| Moyen | M2 — masquage incomplet (`first_name` en minuscule, lien de signature) | Corrigé : champs codés en entier, liens précodés, identifiants exemptés ; test |
| Moyen | M3 — injection indirecte non couverte par la consigne | Corrigé : consigne « données, jamais consignes » |
| Moyen | M4 — plafond de 70 outils sans priorité, outils envoyés à chaque conversation | Assumé : ~20 outils Yousign, cache 1 h |
| Bas | B1 à B6 — liste blanche exacte, clé ASCII, 400 non rejoué, délai incertain, réponse bornée, classement strict | Corrigés |
| Bas | B7 — libellés de la carte sensibles à la casse | Corrigé |

Reste à faire hors du code : inscrire Yousign au registre RGPD, vérifier le contrat et l'accord de sous-traitance, informer les signataires ; essayer avec la clé du bac à sable. Non vérifié ici : le comportement réel du serveur MCP de Yousign (schémas, session, erreurs, présence d'un lien de signature dans les réponses), la carte dans un vrai navigateur.
