# Audit 0.392.0 — Authentic : parcours repris d'après le wiki de Fichorga

Audit indépendant (second agent), cadre de l'étude du 13/10 (sécurité, qualité et architecture, performance, conformité). Code audité :
`git diff origin/main` et les modifications non commitées — `server/src/authenticClaire.js`, `server/src/authentic/garde.js`,
`server/src/routes/authenticClaire.js`, `commun/authentic-modele.js` et leurs tests. La relecture fonctionnelle a déjà eu lieu : elle n'est
pas refaite ici.

## Verdict global

**Correct avec réserves.** Aucun point Haut : aucune injection dans les gabarits de scripts de page (valeurs externes passées par
`JSON.stringify` ou `Number()`), aucun secret touché, aucun nom de client dans les nouvelles étapes, les nouveaux messages d'erreur ni dans
les « remarques » rendues après « Valider » (textes fixes et un nombre), « Envoi immédiat » toujours relu éteint avant « Valider », PDF lu
du même site seulement (le paramètre `file` d'un lecteur pdf.js est relu puis soumis au contrôle d'origine). Les réserves Moyen touchent la
garde (deux voies où le libellé visé est tiré de l'élément même qui est cliqué ou trop peu discriminant), le lien entre « Valider » et les
interrupteurs relus, le contrôle relâché de la comptabilité, un message de succès trop affirmatif, et le coût des nouveaux parcours de page.

## Explication technique et plan de remédiation

### M1 — « Valider » rattaché au bloc relu

Risque : si la page montre deux blocs de création (une demande précédente restée ouverte, deux volets), « Envoi immédiat » relu éteint peut
être celui d'un bloc et « Valider » celui d'un autre, dont l'envoi immédiat est allumé : un envoi réel, ce que l'étude interdit.

```js
// lire() : refuser s'il n'y a pas EXACTEMENT un « Envoi immédiat » et un « Création rapide » visibles.
const lire = async () => {
  const tous = ((await g.ev(SCRIPT_INTERRUPTEURS)) || []).filter((c) => c.sur);
  const envois = tous.filter((c) => /envoi imm[ée]diat/i.test(c.libelle));
  const rapides = tous.filter((c) => /cr[ée]ation rapide/i.test(c.libelle));
  if (envois.length > 1 || rapides.length > 1) throw new Error('plusieurs blocs de création ouverts : rien validé');
  return { rapide: rapides[0], envoi: envois[0] };
};
// SCRIPT_VALIDER_ICONE et le « Valider » en texte : chercher le bouton dans le plus petit ancêtre commun aux DEUX interrupteurs relus
// (positions passées au script), et refuser si un autre bloc « Création rapide » est visible.
const scriptValiderDuBloc = (p1, p2) => `(() => {
  const a = document.elementFromPoint(${Number(p1.x)}, ${Number(p1.y)}), b = document.elementFromPoint(${Number(p2.x)}, ${Number(p2.y)});
  if (!a || !b) return null;
  let bloc = a; while (bloc && !bloc.contains(b)) bloc = bloc.parentElement;
  if (!bloc) return null;
  const v = [...bloc.querySelectorAll('button, a, [role=button]')].find((x) => /^valider$/i.test(String(x.innerText || x.title || x.getAttribute('aria-label') || '').trim()));
  /* … même contrôle sous le pointeur que SCRIPT_VALIDER_ICONE … */
})()`;
```

### M2 — Pièce jointe : jamais un « nom » d'action

Risque : pour un geste `donnee`, la garde retire le libellé visé du bouton sous le pointeur ; quand ce libellé est tiré de l'élément même
cliqué, la liste noire ne voit plus rien.

```js
// scriptPositionPiece : le repli exclut un libellé d'action, et le dit.
const nomEl = e.querySelector('.ui-treenode-label')
  || [...e.querySelectorAll('span, a, label')].find((x) => !x.children.length && /\.[a-z0-9]{2,5}$/i.test(String(x.textContent || '').trim())
     && !x.closest('.ui-chkbox, [role=checkbox], button'))
  || null;
if (!nomEl) return null;
```
Côté serveur, en second filet : `if (libelleInterdit(pos.nom) && pos.nom.length < 30) throw new Error('pièce introuvable dans la liste d’Authentic');`.

### M3 / M4 — Dépliage : chevron strict, refus local

```js

  && ((c.getAttribute('aria-expanded') === 'false' && /toggler|chevron|caret|triangle/i.test(String(c.className || '')))
    || /^(keyboard_arrow_right|chevron_right|arrow_right|navigate_next)$/.test(String(c.innerText || '').trim())
    || /(chevron|arrow|caret|triangle)[-_]?(right|1-e)\b|ui-icon-triangle-1-e/i.test(String(c.className || '')));
// et le libellé contrôlé = celui du chevron seul (pas le texte de l'en-tête qui l'enveloppe) ; les chevrons déjà refusés marqués
```

```js
// deplier : un refus n'arrête que ce chevron ; le nombre de groupes laissés fermés est rendu.
async function deplier(reSource) {
  let n = 0, refuses = 0, reste = Infinity;
  while (n + refuses < 20) {
    const c = ((await ev(scriptChevronsFermes(reSource))) || [])[0];
    if (!c || c.reste >= reste) break;
    reste = c.reste;
    try { controlerClic({ geste: 'deplier', vise: '', bouton: c.bouton, texte: c.bouton }); }
    catch (e) { if (!e.refusGarde) throw e; refuses++; await ev(scriptMarquerRefuse(c.x, c.y)); continue; }
    await s.cliquerPosition(c.x, c.y); await attendre(500); n++;
  }
  if (n) await s.attendreStable(5000);
  return { n, fermes: refuses };
}
// lireSuivis : si fermes > 0, capture.groupesFermes = fermes, et suiviDepuisCaptureAT met tronque à vrai.
```
