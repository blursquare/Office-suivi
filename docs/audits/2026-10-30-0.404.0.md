# Audit et relecture indépendante — CLAIRE 0.404.0 (30/10/2026)

Périmètre : diff non commité de la 0.404.0 — `client/144-canaux-relance-claire.js`, `client/145-conversation-unique.js`,
`client/146-claire-flottante.js` (nouveaux), `server/src/prenoms.js` (nouveau), `server/src/assistantMistral.js` (`masquer`,
`masquerDocument`), `client/49-assistant.js`, `client/63-assistant-conversations.js`, `client/114-canaux.js`, `client/31-emails-dossiers.js`,
`index.html`, `style.css`, `server/src/verificationsTerrain.js`, tests ajoutés, `client/00-version.js`, `CLAUDE.md`, `docs/historique.md`.
Aucun test lancé (`npm run verifier` tourne à côté). Les points de masquage ont été **mesurés** par `node -e` sur `masquer` / `masquerDocument`
de la 0.404.0 et, pour comparaison, sur la version de `HEAD` (0.403.1) recopiée dans le bloc-notes. Les points du poste ont été vérifiés en
relisant le code.

## Verdict global : à corriger avant publication (1 point « Haut »)

Le découpage est propre : un fichier par sujet, des fonctions pures testées. La relance des 15 minutes passe par le chemin habituel de l'agent,
avec les cartes « Autoriser ». La fenêtre flottante réutilise la conversation, sans la recopier.

En revanche, **la liste blanche `MOTS_DROIT` fait passer en clair des noms de famille que la 0.403.1 codait.** Deux cas :

- dans une phrase, un mot à majuscule au milieu de la phrase (« Paul Juge », « Jean Lot », « Bernard Maire ») ;
- dans un document, un titre devant un NOM en capitales (« le Vendeur DUPONT », « Monsieur le Maire GIRARDOT », « le Défunt LEFEVRE »).

C'est une régression de la contrainte n° 1 : des noms absents des fiches partent chez Anthropic. Il faut la corriger avant l'envoi.

Les points « Moyen » touchent la fenêtre flottante :

- elle ne paraît pas tant que la page Discussions n'a pas été ouverte ;
- après un changement de collaborateur, elle continue la conversation du collaborateur précédent ;
- elle se redessine chaque seconde, ce qui peut perdre un clic sur « Autoriser ».

Ils touchent aussi la relance des 15 minutes : elle ne se déclenche presque jamais, et sa dépense n'a pas de plafond. Enfin, le masquage par
prénoms code des noms de rue (« rue Victor Hugo »). L'adresse du bien, qui doit rester en clair, est alors codée elle aussi.

## Explications et remédiations

### H1 / H1′ — la liste blanche `MOTS_DROIT` découvre des noms

**Pourquoi.** Avant la 0.404.0, `masquer` codait tout mot à majuscule hors tête de phrase (`if (!tete) return true`). Le nouveau
`if (MOTS_DROIT.has(m)) return false` est placé **avant** ce test. Il s'applique donc aussi au nom de famille qui suit un prénom.
Dans `masquerDocument`, `gardeMot` sert aux deux places de « Prénom NOM » / « NOM Prénom ». Un titre (« Vendeur », « Maire »,
« Défunt ») en place de prénom fait désormais garder **toute** la paire, NOM en capitales compris. De nombreux noms de famille français
sont dans la liste : Juge, Lot, Maire, Conseil, Chambre, Garant, Caution, Appel, Cour, Office, Partie, Loi, Commune, Service, Livre, Titre,
Domaine… Un tiers, un voisin, un maire ou un défunt absent des fiches part alors en clair chez Anthropic.

**Remédiation.**

1. **Dans `masquer`** : n'exempter un mot du droit que s'il suit un article ou une préposition (« la Cour », « le Vendeur », « du Code »,
   « l'Article »), jamais après un mot à majuscule, un prénom ou un code. Retirer aussi de la liste blanche les mots qui sont des noms de
   famille courants.

```js
// server/src/prenoms.js
const MOTS_DROIT_NOMS_POSSIBLES = new Set(['Juge', 'Lot', 'Maire', 'Conseil', 'Chambre', 'Garant', 'Caution', 'Appel', 'Cour', 'Office',
  'Partie', 'Loi', 'Commune', 'Service', 'Livre', 'Titre', 'Domaine', 'Mixte', 'Banque']);
// server/src/assistantMistral.js, dans masquer(), à la place de `if (MOTS_DROIT.has(m)) return false;`
const apresArticle = /(?:^|[^\p{L}])(?:la|le|les|du|des|de|au|aux|en|par|sur|ce|cet|cette|son|sa|ses)$/iu.test(avant)
  || (i === 1 && /^[LDld]$/.test(morceaux[0]));
if (MOTS_DROIT.has(m) && apresArticle && !MOTS_DROIT_NOMS_POSSIBLES.has(m)) return false;
```

2. **Dans `masquerDocument`** : un titre du droit devant un NOM en capitales garde le titre et code le NOM. L'exemption de la paire reste
   réservée aux `MOTS_NON_PRENOMS_DOCUMENT` (« Article PREMIER », « Code CIVIL »).

```js
const gardePaire = (mot) => MOTS_NON_PRENOMS_DOCUMENT.has(A.normaliserDemande(mot).replace(/[^a-z]/g, ''));
t = t.replace(new RegExp(`(?<![\\p{L}\\[])(${prenom})([ \\t]+)(${capitales})(?![\\p{L}\\]])`, 'gu'), (m, p, esp, nom) => {
  if (gardePaire(p) || gardePaire(nom)) return m;
  return (MOTS_DROIT.has(p) ? p : jeton('NOM', p)) + esp + jeton('NOM', nom);   // « le Vendeur [NOM1] »
});
// même chose pour « NOM Prénom » ; dans la règle « prénom + Nom » mixte, ne garder le Nom que s'il n'est pas dans MOTS_DROIT_NOMS_POSSIBLES.
```

3. **Tests** dans `server/test/masquage-prenoms.test.js` : « J'ai eu Paul Juge », « Jean Lot », « le Vendeur DUPONT déclare »,
   « Monsieur le Maire GIRARDOT », « le Défunt LEFEVRE » → aucun de ces noms dans la sortie.
4. **CLAUDE.md** : ajouter la limite résiduelle à « Limites à connaître ».

### M1 — la fenêtre flottante n'apparaît qu'après un passage par Discussions

`claireFlottanteVisible(…, !!assistantDisponibilite.agent, …)` reste faux tant que `chargerDisponibiliteAssistant()` n'a pas tourné. Or seul
`initAssistant` l'appelle (client/49:20). Remède : l'appeler au démarrage, puis toutes les 5 minutes, depuis `demarrerClaireFlottante` :

```js
function demarrerClaireFlottante() {
  chargerDisponibiliteAssistant();
  setInterval(() => { chargerDisponibiliteAssistant(); }, 5 * 60 * 1000);   // la fonction ne relit qu'au-delà de 60 s
  setInterval(majClaireFlottante, 1000);
}
```

### M2 — la conversation du collaborateur précédent est continuée

`definirUtilisateurPoste` appelle `quitterCanal()` mais ne recharge pas les conversations personnelles. La fenêtre flottante, qui ne passe pas
par `initAssistant`, garde donc `assistantMessages`, `assistantAgentConversation` et `cleConversationsChargees` de l'autre personne. Remède :
recharger à chaque envoi et à chaque ouverture de la fenêtre (`chargerConversationsAssistant` détecte déjà le changement de clé et remet tout
à zéro, carte en attente comprise) :

```js
async function envoyerDepuisClaireFlottante() {
  chargerConversationsAssistant();   // nouveau collaborateur sur le poste : sa conversation, jamais celle du précédent
  …
}
function basculerClaireFlottante(force) {
  chargerConversationsAssistant();
  …
}
```

Le mieux est aussi d'appeler `chargerConversationsAssistant()` à la fin de `definirUtilisateurPoste`, pour la page comme pour la fenêtre.

### M3 — redessin chaque seconde

Ne redessiner que si quelque chose a changé, et ne recoller en bas que si l'on y était :

```js
var signatureClaireFlottante = '';
function renderClaireFlottante() {

  const enBas = zone.scrollHeight - zone.scrollTop - zone.clientHeight < 40;
```

### M4 — la relance ne se déclenche presque jamais

Les conditions (auteur, canal ouvert, page Discussions affichée) sont prudentes : une seule réponse, pas d'action en arrière-plan. Mais elles
vident la fonction de son sens. Deux voies :

- Faire tourner la relance par le **serveur** : un tour par minute dans le planificateur des routines, avec la règle de
  `questionsSansReponseCanal` placée dans `commun/`. Le serveur dépose alors une proposition, ou un message de CLAIRE qui renvoie l'auteur
  vers le fil. La réponse elle-même reste faite par le poste qui ouvre le fil : l'agent tourne sur le poste.
- Au minimum, lancer la relance dès que l'auteur a le canal ouvert, sans exiger l'écran Discussions (`ecranAffiche`), et **dire à l'étude**
  dans le résumé de version que la réponse ne part que si l'auteur rouvre le canal.

### M5 — dépense sans plafond

Compter les relances dans le plafond des routines : le serveur refuse au-delà de `routines-usage`. Ou les limiter, par exemple à 10 par jour
et par collaborateur (clé locale datée), et à Sonnet par défaut :

```js
const cleJour = 'claire-relances:' + utilisateurPoste + ':' + isoAujourdhuiLocal();
const n = Number(localStorage.getItem(cleJour) || 0);
if (n >= 10) return;
ecrireLocal(cleJour, String(n + 1));
```

### M6 — les noms de rue sont codés comme des personnes

Ne pas appliquer la règle « prénom + Nom » juste après un mot de voie, ni sur une suite qui fait partie d'une adresse des fiches :

```js
const VOIE = /(?:^|[^\p{L}])(?:rue|avenue|av\.|boulevard|bd|place|allée|allee|chemin|impasse|quai|square|cours|route|faubourg|lieu-dit)\s+$/iu;
t = t.replace(regexPrenomMixte, (m, p, esp, nom, pos, tout) => {
  if (VOIE.test(tout.slice(Math.max(0, pos - 16), pos))) return m;
  …
});
```

Ajouter le test : « 12 rue Victor Hugo, BLOIS » (adresse des fiches) reste en clair.

## Points demandés

- **HTML des anciens messages (sujets précédents, fenêtre flottante) — pas de nouvelle XSS.** `m.html` vient des conversations du
  **même collaborateur sur ce poste**. Elles sont lues dans `localStorage` sous `claire-assistant-conversations:<collaborateur>`, et ce HTML
  est déjà rendu tel quel par la page Discussions depuis le 12/10. Les demandes passent par `htmlTexteCanal` (échappé). Les réponses sont
  écrites par le code (`escapeHtml`, mise en forme après échappement). Les titres des sujets passent par `escapeHtml`, et l'identifiant par
  `escapeOnclickArg`. La fenêtre flottante n'affiche jamais un fil de canal (`if (canaux.actif)` → texte fixe), donc aucun HTML venu du
  serveur. Seule surface : un script déjà présent sur l'origine pourrait écrire dans `localStorage`, ce qui ne change rien au risque
  existant. Le défaut réel est fonctionnel (B9).
- **« (Écran ouvert : …) » envoyé à l'IA** : seuls des libellés fixes de `LIBELLES_ONGLETS` partent, sans donnée de client. Ce point est
  conforme. Mais le masquage abîme le libellé, et le préfixe pollue la bulle et le titre (B1).
- **Coût de la relance** : voir M5. Un tour d'agent sur un dossier coûte de l'ordre de quelques dizaines de centimes à plus d'un euro avec
  Opus. Le volume est aujourd'hui faible, à cause de M4. Corriger M4 sans M5 ferait croître la dépense sans limite.
- **Carte « Autoriser » en attente** : un nouveau sujet ne peut pas s'ouvrir pendant qu'une carte attend. La boucle de l'agent tient en
  effet `assistantEnCours` / `assistantTraitementEnCours`, et `occupeAssistant()` bloque l'envoi depuis la page, la fenêtre flottante et la
  relance. Les clés `assistantActions` de la fenêtre (`${i}-${j}`) sont les mêmes que celles de la page (`entreesFilClaire` garde l'index
  `i` de `assistantMessages`) : aucun bouton périmé, sous réserve de M3.
- **`canaux.actif` pendant une demande depuis la fenêtre flottante** : `quitterCanal()` n'est appelé qu'après `occupeAssistant()`. Une
  demande en cours dans un canal, relance comprise, n'est donc jamais détournée par la fenêtre. Seul `definirUtilisateurPoste` peut appeler
  `quitterCanal()` pendant une demande de canal : la réponse de CLAIRE tombe alors dans la conversation personnelle du nouveau
  collaborateur. Ce défaut existait avant la 0.404.0.
- **Double réponse de la relance** : impossible depuis le poste d'un autre collaborateur (filtre `m.auteur === utilisateurPoste`). Si
  l'auteur est le responsable du canal, CLAIRE a déjà répondu tout de suite (`claireDoitRepondreCanal`) : la question est donc « répondue ».
  Reste le cas B7.
