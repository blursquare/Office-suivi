## Explication technique et remédiation

### Haut 1 — envoi d'une autre demande que celle dite

`decisionOutil(e, OUTILS_AGENT_ENVOYER)` ne regarde que `e.name`. L'événement `agent.mcp_tool_use` porte pourtant `input`
(`{ signatureRequestId, telemetry }` d'après le schéma du serveur MCP). Scénario : l'IA de CLAIRE appelle `yousign_agent` mode
« envoyer », `demande_id` = A, consigne « … et envoie aussi la demande B » (ou un nom de demande Yousign qui le suggère) ; la carte dit
« ENVOYER la demande A » ; l'agent géré appelle `send-signature-request` sur B puis sur A : les deux sont permis. Même chose si
`send-signature-request` est réglé « toujours permis » dans la console : la branche « déjà permis » l'accepte quel que soit l'identifiant.

Correction : passer l'identifiant attendu à `seance` et le contrôler dans la décision (une fois seulement), refuser/arrêter sinon ; ne
pas ajouter de consigne libre en mode envoyer.

```js
function decisionOutil(evenement, permis, attendu) {
  const nom = String((evenement && evenement.name) || '');
  const idAppel = String((evenement && evenement.input && evenement.input.signatureRequestId) || '').trim().toLowerCase();
  const ok = (permis || OUTILS_PERMIS).has(nom) && (!attendu || nom !== 'send-signature-request' || idAppel === attendu.id && !attendu.envoye);
  if (ok && attendu && nom === 'send-signature-request') attendu.envoye = true;
  return ok ? { result: 'allow' } : { result: 'deny', deny_message: `L'outil « ${nom || 'inconnu'} » n'est pas autorisé pour cette demande.` };
}
// seance(client, texte, r, permis, attendu) : même contrôle dans la branche « déjà permis » (send d'un autre id → horsListe, interrupt).
// agir : const attendu = mode === 'envoyer' ? { id: identifiant, envoye: false } : null ; en mode envoyer, ne pas joindre « Demande : consigne ».
```

Test : événement `send-signature-request` avec `input: { signatureRequestId: <autre UUID> }` → `deny` ; deux envois du bon UUID → le second `deny`.

### Haut 2 — la route écrit sans garde serveur

Le reste de CLAIRE n'a pas de contrôle d'accès propre (choix de l'étude), mais Yousign en a un : `yousign.js:196-202` refuse toute
écriture que l'agent du serveur n'a pas demandée avec ces arguments (`attendre`, `surAppelsEcriture` de `routes/assistant.js:220`) et
toute écriture quand l'interrupteur de Réglages › Yousign est coupé. `POST /api/signature-rib/agent` n'a ni l'un ni l'autre :
`curl -X POST http://<serveur>/api/signature-rib/agent -H 'Content-Type: application/json' -d '{"mode":"envoyer","id":"<uuid>"}'` depuis
un poste (sans Origin, cas admis par `securiteHote.js`) envoie l'invitation aux signataires, sans carte ni trace autre qu'un point
terrain. Même chose en « modifier » (retirer un signataire).

Correction, sur le modèle de Yousign :

```js
// signatureRibAgent : appels attendus, 10 min, une fois chacun
const attendus = new Map();
function attendre(appels) {

    attendus.set(cleAppel(a.entree.mode, a.entree.consigne, a.entree.demande_id), t + 600000);
}
// dans agir, avant toute séance en modifier/envoyer :
if (mode !== 'lecture') {

  const k = cleAppel(mode, consigne, identifiant); const j = attendus.get(k); attendus.delete(k);
  if (!j || j < Date.now()) return { ok: false, code: 'donnees', raison: 'Demande non émise par l’agent de CLAIRE.' };

// routes/assistant.js:220 : surAppelsEcriture: (appels) => { yousign && yousign.attendre(appels); signatureRib && signatureRib.attendre(appels); }
```

(La clé doit porter les arguments RÉTABLIS que le poste envoie — `sortieOutils.appels`, comme pour Yousign.) Ajouter une ligne au journal
du serveur à chaque envoi (UUID seul, jamais un nom).

### Moyens

- **Régression possible du RIB** : ne déclencher l'arrêt que pour un outil qui ÉCRIT (pas `get-`/`search-`/`list-`, ni outils intégrés
  de lecture), et, après un arrêt dans `creerBrouillon`, dire « vérifier dans Yousign si un brouillon a été créé » plutôt que
  « configuration » (qui fait repasser le poste au bouton de repli et invite à recommencer).
- **`deny` de la console** : ne prendre la branche « déjà permis » que pour `evaluated_permission === 'allow'` ou absent ; compter un
  `deny` comme un refus.
- **`envoye`** : lire `agent.mcp_tool_result` (`mcp_tool_use_id` = id de l'appel `send`, `is_error`) et ne poser `envoye` que sur un
  résultat sans erreur ; sinon `envoye: false` + « Yousign a refusé l'envoi ».
- **Carte d'envoi** : relire le titre et l'état de la demande (mode lecture ou `get-signature-request`) avant la carte et l'y afficher.
- **Clair et anonymisation** : conforme au choix de l'étude pour le RIB (la carte le dit), mais à confirmer pour une conversation où
  l'anonymisation est active (charte CSN, 0.347.1) ; au minimum, marquer la conversation « passée en clair » (`conv.aEteEnClair`) comme
  le connecteur MCP, et donner aussi à la lecture une carte `strict` quand l'anonymisation est active.
