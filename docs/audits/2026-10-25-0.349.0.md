# Audit — 0.349.0 (25/10/2026) : veille notariale (CNAF, CRIDON), pastille et notifications Windows

Second agent en lecture seule, cadre de l'étude du 13/10 ; relecture indépendante à part. Fichiers lus en entier : `server/src/routines/veille.js`,
`planificateur.js`, `ia.js`, `server/src/relaisWord.js`, `routes/relaisWord.js`, `server/relais/CLAIRE-relais.cs`, `client/122-notifications.js`,
`server/src/parametres/assainir.js`.

## Verdict

**Correct avec réserves → publiable après corrections.** Le point Haut et les points Moyens sont corrigés ; restent quelques points Bas.

## Points relevés

| Gravité | Point | État |
|---|---|---|
| Haut | La route du relevé ne rendait au relais ni la pastille ni les notifications (vidées au passage) : la fonctionnalité ne faisait rien | Corrigé : `pastille` et `notifications` dans la réponse, test de route |
| Moyen | Emails du CRIDON reconnus par le seul domaine (réponse à une CONSULTATION, faits d'un dossier) ou par le seul objet, quel que soit l'expéditeur (client qui répond « RE: Flash CRIDON ») ; domaine « evilcridon » accepté | Corrigé : domaine en .fr qui COMMENCE par « cridon » ET objet magazine/flash/lettre/newsletter/actualité ; jamais une réponse, un transfert, une consultation |
| Moyen | Changement de collaborateur : la remise à zéro de la pastille n'était jamais appelée (comparaison après l'affectation) | Corrigé |
| Moyen | Route `/pastille` : texte libre d'une bulle Windows posé par n'importe quel poste ; `Map` du serveur sans limite | Corrigé : le poste n'envoie qu'une rubrique et un nombre, le SERVEUR écrit le texte (`TEXTES_NOTIFICATIONS`) ; seulement un collaborateur dont le relais est installé ; 100 postes au plus |
| Moyen | Toutes les rubriques calculées toutes les 5 s, même éteintes (« Aujourd'hui » parcourt tous les dossiers et écrit dans le navigateur) | Corrigé : seules les rubriques allumées |
| Moyen (relecture) | Une proposition de CLAIRE comptée deux fois (message non lu de son canal et « À traiter ») | Corrigé : les messages non lus ne comptent que ceux des personnes (`nonLusClaire` rendu par le serveur) |
| Bas | Relectures des canaux fenêtre cachée sur tous les postes, même sans relais | Corrigé : seulement si le relais du collaborateur est installé |
| Bas | Nouveautés perdues si l'envoi échoue | Corrigé : tenues pour annoncées après la réponse du serveur |
| Bas | Page du CNAF dont la présentation change = « rien de neuf » silencieux | Corrigé : « structure de la page non reconnue » au journal |
| Bas | Entité HTML hors Unicode : la veille tombait | Corrigé |
| Bas | `content-length` de plus de 2 Mo lu quand même | Corrigé (refusé d'après l'en-tête) |
| Bas | Liens cliquables de la veille vers toute adresse https (texte venu de l'extérieur) | Corrigé : seulement vers le site du CNAF |
| Bas | Relais : une erreur d'affichage pouvait ouvrir une boîte « exception non gérée » | Corrigé : rien ne remonte dans la boucle de messages |
| Bas | Plusieurs fenêtres CLAIRE du même collaborateur : bulles en double | Laissé (rare ; une fenêtre par poste) |
| Bas | Code d'installation (jeton) affiché dans la fenêtre d'information | Laissé : nécessaire si le presse-papiers a changé ; le relais le vide |
| Bas | Troisième copie de `connexionPrete` ; 300 emails lus au plus pour trouver les lettres du CRIDON | Laissé (sans effet immédiat) |
