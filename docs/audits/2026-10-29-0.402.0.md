## Explication technique et remédiation

### M1 — Noms rétablis puis remasqués trop légèrement

Chemin : texte du document masqué FORT par `masquer(texte, sensibles, table)` (sans `adresses`, donc ancien masquage complet : même
« Garnier » en tête de ligne est codé) → Claude écrit `emetteur: "[NOM1] Plomberie"` → `retablirTexte` → en base « Garnier
Plomberie » → l'agent appelle `chercher_nas` → `masquerValeur` sous la politique couplée (conversation avec `adresses`) exempte le
premier mot d'une phrase → « Garnier » part en clair. Vérifié :

```
masquerValeur({ emetteur: 'Garnier Plomberie', pj: 'Dupont_compromis.pdf' })  →  "Garnier [NOM1]", "Dupont_compromis.pdf"
masquerValeur({ e2: 'Émetteur : Garnier Plomberie' })                          →  "Émetteur : [NOM2] [NOM1]"
```

Remédiation (même technique que l'objet et l'aperçu de `chercher_mails`) — `routes/indexNas.js` :

```js
const pref = (lib, v) => (v ? `${lib} : ${v}` : '');
```

`emailsDossiers.js` `lireMailTrouve` — ne pas envoyer le nom des pièces jointes (règle déjà tenue pour les pièces jointes de

Ajouter les deux cas (« Garnier Plomberie » en `emetteur`, « Dupont_compromis.pdf ») au test « rien de nominatif » avec des

### M2 — Pièces personnelles reconnues par le nom seulement

```js
const RE_NOM_SENSIBLE = /(identit|passeport|\bcni\b|\bpi\b|carte (nationale|vitale)|titre de s[ée]jour|\brib\b|\biban\b|livret de famille|permis de conduire|avis d.?imposition|bulletin de (paie|salaire)|releve de compte)/i;
function cheminSensible(chemin) {
  const n = String(chemin || '').normalize('NFD').replace(/[̀-ͯ]/g, '').replace(/[_\-.]+/g, ' ');
  return RE_NOM_SENSIBLE.test(n);
}
// Dans resumerDocuments, après lecture du texte : jamais une bande MRZ ni un IBAN.
const RE_CONTENU_SENSIBLE = /[A-Z0-9<]{25,}<{2,}|\bFR\d{2}(?:\s?[A-Z0-9]{4}){5}/;
if (RE_CONTENU_SENSIBLE.test(texte)) { /* même traitement que cheminSensible */ }
```

derniers résultats.

## Points vérifiés sans remarque

- XML EWS : `echapperXml` sur la QueryString et les ItemId ; dossiers EWS constants (`inbox`, `sentitems`).
- SQL : constantes seulement dans les fragments construits (`LIKE 'd:%'`), tout le reste en paramètres ; `MATCH` par `requeteFts`.
- NAS : `dossierClientAbsolu` + `cheminDocumentMemoire` (chemin réel contrôlé), tout en `fs/promises`, aucune écriture ; un document
  se désigne par son identifiant en base, jamais par un chemin reçu du réseau ; flux par `envoyerFlux`.
- Disjoncteur : `lectureAgendaSuspendue` avant chaque appel, `signalerIdentifiantsRefuses` sur 401/403, un seul essai.
- Secrets : mot de passe Exchange et clé Claude jamais renvoyés ni journalisés.
- Masquage : prompt du résumé masqué fort par le serveur ; résultats des trois outils par `masquerValeur` (objet et aperçu préfixés,
  `nom` codé en entier, adresses codées) ; `lire_mail` et `chercher_nas` comptés dans la limite de lecture ; codes inventés effacés.
- Poste CLAIRE : `PUT /index-nas/reglages`, `parcourir`, `resumer` refusés ; seules les deux recherches de messagerie (lecture en POST)
  ajoutées à `PERMIS_ECRITURE`.
- Coût : 5 documents toutes les 5 min, 5 000 caractères au plus, budget propre de 15 € par mois (`index-nas-usage`) contrôlé avant chaque
  appel ; résumé périmé (fichier relu pendant l'appel) jamais gardé.
- Rendu : aucun texte venu du serveur n'est injecté sans contrôle dans le HTML ajouté (compteurs numériques seulement ; aucun nom de
  fichier de client à l'écran).
- `routeAsync` sur toutes les routes asynchrones ajoutées.
