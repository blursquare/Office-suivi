# Audit 0.329.0 — photos de profil des collaborateurs

**Verdict : pas de point « Haut ».** Audit fait par l'agent de développement ; la relecture indépendante par un second agent reste à passer avant tout envoi sur `main`.

| Sujet | Niveau | Constat | Remédiation |
|---|---|---|---|
| Sécurité — image servie | Bas | Seules des chaînes `data:image/jpeg;base64,…` validées par expression régulière sont posées dans une balise `<img>` ; le serveur refuse tout autre format (signature `/9j/`), plus de 150 Ko, ou un nom hors liste fermée. | Aucune. |
| Sécurité — accès | Bas | Comme le reste de CLAIRE sans mot de passe, un poste du réseau peut changer ou retirer une photo (identité déclarée par le poste). | Accepté par l'étude (24/10). |
| Conformité (RGPD) | Moyen | Une photo est une donnée personnelle du collaborateur, gardée sur le serveur du bureau, jamais envoyée à une IA ni dans le rapport technique. | Inscrire la photo au registre des traitements ; ajouter le consentement du collaborateur si besoin. |
| Performance | Bas | ≈ 10 Ko par photo, 3 photos, relues toutes les 5 minutes (≈ 30 Ko). Le tableau de bord se redessine une fois si les photos changent. | Aucune. |
| Qualité | Bas | `initialesAuteurCanal` supprimée (doublon de `initialesCollaborateur`) ; test serveur et test du poste ajoutés ; jouée dans Chromium (dépôt, Suivi, canal). | Aucune. |
